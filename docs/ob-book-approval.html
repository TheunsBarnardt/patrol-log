2. What this document covers

The new Patrol Log system will replace the current Sierra 1 Occurrence Book for logging incidents. This BRD sets out the lists and rules so the book matches how the sector actually works.

  • The types of incident (Criminal, Emergency, Of Interest, Other) and their SAPS-style codes
  • For criminal types only: a danger level that tells a patroller whether to attend, or leave it to police and armed response
  • Medical patient priority (P1–P4) — how badly the injured person is hurt, not how dangerous the scene is
  • How an incident is opened and closed (Active / Closed, and the conclusion list)
  • Who an incident can be received from, and which services can be marked on scene
  • The suburb list for Wierdabrug / Centurion
  • How patrollers log an incident on the phone, including while already on patrol
  • How call centre logs a Commence Shift in the book
  • How BOLOs are shown to patrollers
  • That photos are kept as proof on each incident
  • How hotspots are filled from last month’s crime (not accidents), and can still be amended by admin
  • How the monthly Summary Report, WhatsApp community post, Detail report and crime map work
  • Related Patrol Log gaps: one vehicle, several patrollers; patrollers add/edit Residents
Nothing in this document is software yet. It is the business specification we will build from.

3. How an incident will work

Every event that belongs in the book becomes one Occurrence Book entry (an incident).

3.1 OB / IR number — per sector, per year

Today Sierra 1 uses sequence/year, for example 215/2026. Le Roux asked whether each sector has its own sequence. Yes.

Format: {sector}/{sequence}/{year} — example S1/215/2026 (Theuns). WBS2 would be S2/1/2026, WBS3 would be S3/1/2026. Sequence restarts at 1 each calendar year, separately per sector. The number is assigned on first save and is not typed by the operator.

3.2 Capture — crime vs emergency

Le Roux (agreed with Sector 2’s practice on emergencies):

  • Crime — capture everything the sector knows about, even if nobody from CPF was on scene. That is how we see trends and hotspots. Those rows use conclusion Captured for Information Only.
  • Emergencies, natural disasters and by-law (flood, lightning, fireworks, MVA, fire, medical) — only capture if we were present or actually assisting. If we only phoned Metro and were not needed, do not log it.

3.3 How a row is filled

  1. Someone captures the incident (call centre on the admin website, or a patroller on the phone).
  2. They choose the category, then one or more types (for example House Robbery and Theft and Assault GBH and Malicious Damage). The first type is the primary one for reports. Extra types record everything else that happened. Code 108 is Robbery from Person.
  3. For a criminal type they also mark Alpha (A) — still active or Bravo (B) — already happened. That drives the danger level (Le Roux: 023A leave to police; 023B patrollers can assist).
  4. They fill in date and estimated time, where it happened, a description, who reported it, and who responded.
  5. The entry stays Active until someone closes it.
  6. To close it they must choose a conclusion (what the outcome was).
  7. Photos can be attached as proof at any time.
What we are not changing: Commencing and standing down a patrol stays as it is today. A patrol is not the same thing as an incident. A patroller can be on patrol and then log or respond to an incident without ending the patrol.

5. Status and conclusions

5.1 Status — only two

StatusMeaning
ActiveStill open. Work is ongoing or waiting for feedback.
ClosedFinished. A conclusion has been chosen.

There is no “pending”, “investigating” or “false alarm” status. If it was a false alarm or nothing was found, that is recorded in the conclusion, then the incident is Closed.

5.2 Conclusions — choose one when closing

These are the same outcomes used in the current Sierra 1 book. Please confirm the wording is still what you want operators to see.

2Authorities notifiedSAPS / Metro / other authority was informed; we are not holding the scene.
3No feedback receivedLogged, but nobody came back with an outcome.
4Scene Handed over to AuthoritiesWe were on scene and handed it to SAPS / Metro / Fire / EMS.

6. Two different ideas — do not mix them

These are not the same thing. How badly an injured person is hurt is not the same as how dangerous the scene is for a patroller. We do not put a P1–P4 “urgency” on the incident type. That old number mixed those ideas together and is dropped.

6.1 Danger level — Alpha (A) vs Bravo (B)

Le Roux: the same crime is not equally dangerous when it is still happening as when it is already over.

Radio / codeMeaningExample (Armed Robbery 023)
Alpha / AActive — still in progress023A — leave it to the police and armed response
Bravo / BAlready happened — scene after the fact023B — patrollers can assist
Charlie / CAttempted (already a separate type on the list, for example 023C Attempted Armed Robbery)If it is still on, treat like Alpha; if it is over, treat like Bravo

So danger is not one fixed label on “Armed Robbery”. The operator picks the type(s) and whether it is Alpha or Bravo. The phone then tells the patroller what to do.

Starting rule (the group can move any row):

  • Contact / serious crime, Alpha → Leave to police
  • Same crime, Bravo → Caution (patrollers may assist)
  • Property crime, Alpha → Caution (suspect may still be there)
  • Property crime, Bravo → Respond
  • Book-only types (fraud, DUI, recovered goods) → No response either way

Emergency, Of Interest and Other types still have no danger level.

Danger levelWhat the patroller must do
Leave to police Do not attend the scene. This is for SAPS and armed response only. If you are already nearby, stay at a safe distance and observe. Do not approach armed suspects, a shooting, a hijacking, a hostage situation, or similar.
Caution You may attend if asked or if you are already close, but treat the scene as still dangerous. Do not go in alone if suspects may still be there. Wait for backup or armed response if needed.
Respond Normal CPF attendance. Go, check, help residents, take details and photos, and write it in the book.
No response For the book only. No need to send a patroller unless someone specifically asks.

Danger follows the contact / property / book-only rules above. Mark any type that should move.

6.2 Medical patient priority — the injured person only

P1–P4 is used only as an optional tag for a person who was hurt (or for a deceased person). It is the condition of that individual, not the danger of the scene, and not “how urgent is this incident type”.

Example: an MVA can have one patient tagged P1 (critical) and another tagged P3 (walking wounded). The accident type itself has no priority and no danger level.

Patient tagMeaning for that person
Injuries - P1Code Red — life and death / critical
Injuries - P2Code Yellow — hurt but not critical
Injuries - P3Code Green — walking wounded / stable
Injuries - P4Code Blue — deceased

14. Photos

Each incident can have one or more photos. This is required as proof (scene, vehicle, open gate, injuries context, and so on).

  • Call centre and patrollers can both add photos.
  • Photos stay with that OB number and are not public on the internet.
  • They are stored securely (Cloudflare R2). The free allowance is large enough for normal sector use (about 10 GB per month included).

15. Patrollers — log and respond while on patrol

A patroller must be able to put something in the book without first going back to the office, and without standing down.

15.1 Log a new incident

From Home, or from the live patrol screen. Typical examples: they come across an open gate, or they walk into a house breaking while already patrolling.

On the phone they fill in a short form: type, time (defaults to now), suburb, street (GPS can help), description, photos. “Received from” defaults to CPF Patroller. Their call sign and sector are filled in automatically.

15.2 Respond to an incident that is already open

If the call centre (or another member) already logged it, the patroller can tap Responding and choose that active incident. If the danger for the chosen Alpha/Bravo is Leave to police (for example 023A), the phone must warn them not to approach — that incident is for SAPS and armed response. On 023B they may assist with caution.

  • The patrol does not end.
  • The live map will show that unit as Responding (this patrol type already exists when starting a patrol; now they can switch to it mid-shift).
  • When they are done they resume the original patrol type (foot, vehicle, and so on).

They can also start a patrol already as Responding, but they must then link or create the incident.

16. Call centre — Commence Shift in the book

In Sierra 1, “Commence Shift” is often written as a row in the OB Book. In Patrol Log, commencing a patrol is already a separate action for patrollers.

For a member whose role is call centre agent, there will be an optional button: Log Commence Shift. That creates one Other / Commence Shift entry (sector, call sign, time). It is not created automatically when a patroller starts a patrol.

17. BOLOs — last seen where and when

When admin or call centre captures a BOLO, Vehicle of Interest or Person of Interest, patrollers must be able to look it up on the phone.

Each item on that list shows:

  • What to look for (type, description, vehicle and/or person details)
  • Where last seen (suburb and street)
  • When last seen (date and time)
  • Photos if any

If a patroller sees that vehicle or person, they can add a short “seen here now” update. That becomes the new last-seen place and time for everyone else.

18. Hotspots — last month’s crime trends

The live map already has admin-drawn hotspot circles. Those will stay, but they will also be filled from the book.

  • The system looks at criminal incidents only from the last month (for example armed robbery, house breaking, theft, wall jumpers). Accidents, fire, medical and other emergencies do not create hotspots.
  • Where several crimes cluster in the same area, a hotspot is suggested or updated so patrollers can see last month’s trend.
  • Admin can still amend every hotspot: add one, move it, change the size or rating, or delete it if the trend is wrong or outdated.
  • A hotspot that admin has edited by hand is not blindly overwritten. The trend is shown; a person decides whether to keep the change.
In short: hotspots follow last month’s crime pattern, not accidents, and a person can always correct the map.

19. Reports

Sectors still on Telegram pull stats by hand. The new book must print and copy the same reports Sierra 1 already posts, so stats are not manual. 19.1 WhatsApp community summary

Posted to CPF community groups. Crime incidents only. Exclude rape and suicide. Strip street numbers (road / suburb only). Filter by date range.

Heading example:

Wierdabrug Sector 1
Crime Incidents Summary Report
(1 - 31 August 2026)

Each row:

  • Date and time (24-hour)
  • Suburb — Type (code) — street name only (no house number). Extra tag in the heading if used, e.g. Wall Jumper
  • Day of week — Time of day band (e.g. Saturday - Afternoon (12:00 - 16:00))
